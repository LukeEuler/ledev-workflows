# Common Review Rules

## 重点

优先检查：

- 用户目标是否达成，是否多做、少做或做偏。
- 行为正确性和边界条件。
- 错误处理、重试、回滚、幂等和可诊断性。
- 数据一致性、顺序、去重、事务和兼容性。
- 外部 API、配置、权限、认证、分页、限流和超时。
- 并发、生命周期、取消、资源释放和共享状态。
- 数值精度、溢出、时间时区、编码和序列化。
- 测试覆盖是否与风险匹配。

## 审查方式

- 同时看最终 diff 和提交序列。
- 读取变更代码的调用方、被调用方和契约定义。
- 对 shared behavior、公共 API、数据格式、配置格式、迁移和权限变更扩大上下文。
- 对局部实现保持窄范围，不顺手评审无关历史代码。

## 测试判断

检查是否有：

- 聚焦单元测试或集成测试覆盖新增行为。
- 回归测试覆盖修复的 bug。
- 失败路径、空值、边界值和并发/顺序风险。
- 迁移、配置和兼容性验证。

测试缺失不一定是 blocker；按风险判断严重级别。
