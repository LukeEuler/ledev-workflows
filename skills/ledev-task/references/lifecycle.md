# 归档、恢复与 state 收敛

本文件仅在 archive、restore 或用户要求整理 state 时读取。第一版保留独立任务原文、附件和日志，不压缩、不删除历史、不自动合并。工具开发不授权整理目标项目的历史任务。

## 操作与资格

- `archive` / `归档` 不带编号：只读评估全部已结束、未归档任务，报告“可归档 / 不可归档 / 待确认”、依据、预计移动文件、引用改动及未解决问题；不得写任务、索引、state 或 ignore。
- `archive T010 T011`：用户授权归档这些任务；重新评估、整批预检后执行。任一不合格则整批不移动。已归档的任务报告现状，不重复移动。
- `restore T010` / `恢复 T010`：恢复原位置，保留状态；重新开展工作另用 continue 或 restart。已在活动目录则报告现状；原位置冲突则停止，不覆盖。
- 日期只决定评估顺序，最早结束者优先；无 Completed 时间的单列并按编号排序，不从 mtime 或编号推断完成日期。
- 指定编号即授权执行，不增加固定二次确认；责任、附件或引用存在实质歧义时，只澄清该歧义。

仅 done / obsolete 可归档。逐项语义核对：没有尚未完成的验收、阻塞或由本任务继续承担的责任；后续事项已完成、明确取消或移交到具体任务；长期有效的说明、约束、操作步骤已有适当去处（无此类内容写不适用）。不要求每个任务新增总结文档。脚本检查不是语义评估的替代。

已完成子任务不因主任务未完成而禁止归档。区分历史参考、等待交付和仍承担跟进责任；核对交付和移交，不根据入站引用数量决定资格。

## 持久记录

归档正文放在 `tasks/archive/YYYY/`，YYYY 为归档时间在项目时区的年份；未配置使用本地时区。正文第一行改为 `[返回任务索引](../index.md)`。其他字段及模板 marker 保留，不改变 Status / Phase。

沿用任务的列表元数据，使用：

```markdown
- Completed: 2026-11-01
- Archived: 2026-11-12T10:30:00+08:00
- Archive Original Path: .ai/ledev/tasks/T010-example.md
```

新增 `## Archive Record`，记录归档资格依据、责任移交目标、长期说明去处、附件归属、正文和独占附件的项目相对原路径 → 归档路径映射（即使没有附件也记录正文）。共享附件列明保留位置；不写本机绝对路径。多个归档周期追加事件，当前字段指向最新周期。

恢复读取最新映射，但根据当前文件内容重新计算引用；保留归档期间的修改。移除当前 Archived 和 Archive Original Path 字段，Archive Record 和归档/恢复历史事件保留。Completed 不改变。close 成为 done / obsolete 时记录实际 Completed 时间；旧任务不凭空补日期。

## 附件与链接预检

1. 用共享定位规则找正文并检测重复编号；读取正文、待办、验收、移交目标。
2. 清点独占附件、共享附件和归属不明附件。不能仅靠 T 编号文件名判断归属。独占附件随正文移动并保留内部相对结构；若跨任务独占文件目标冲突，应保留额外子目录并重算链接；共享附件不移动；归属不明则停止该批次。
3. 扫描整个目标仓库的入站与出站引用，包括 Git 忽略的 `.ai/ledev/`、其他任务、reviews、state、项目文档；跳过 .git、依赖目录和二进制。扫描范围或权限不完整须报告，不得宣称全量检查通过。
4. 处理 Markdown 普通链接、图片、引用式链接、相对路径及仓库根路径。按每个引用文件的新位置计算目标，保留锚点和查询串，正确处理 URL 编码、空格及括号。保留未受影响的内容；不对代码块或普通文本全局替换。
5. 普通文本、HTML、代码片段、外部系统路径另行报告，给出处理方式；无法保证无损的引用先解决再执行。原有失效链接单列，迁移不得新增失效链接。
6. 校验所有目标不存在、路径均在项目内、无符号链接绕出范围；检查任务正文唯一性、附件完整性、模板第二行、返回索引和全部受影响链接。

## 一致性执行

语义评估、附件归属和 Markdown 链接转换由 agent 结合仓库完成。不要假定通用正则能安全解析所有 Markdown。确定性文件提交使用 `scripts/task_transaction.py`，而不是先 mv 再逐项修补。

先在临时目录构造完整的迁移后文件树并校验；用实际生成脚本在临时项目根生成两级索引。最终计划包含正文、附件、入站/出站引用、两级索引和必要的 state 路径更新。state 历史收敛是独立工作，不随归档顺带删除内容。

计划 JSON 格式：

```json
{"files": [
  {"path": ".ai/ledev/tasks/T010-example.md", "before": "源文件字节的SHA256", "content": null},
  {"path": ".ai/ledev/tasks/archive/2026/T010-example.md", "before": null, "content": "完整迁移后正文"}
]}
```

`before: null` 要求目标不存在；`content: null` 表示删除源文件。所有改写文件均须带原字节 SHA256。移动文件时在目标条目增加 `mode`（原文件的权限整数，如 493 表示 0755），保留执行权限；回滚会恢复原文件权限。路径相对项目根，不能包含 `..`、.git 或符号链接。文本计划支持 UTF-8；二进制附件不可转码，使用 `content_base64` 字段替代 `content`，填入原始字节的 base64 编码。计划先只读预检，再提交：

```sh
python3 <skill>/scripts/task_transaction.py <project> <plan.json>
python3 <skill>/scripts/task_transaction.py <project> <plan.json> --apply
python3 <skill>/scripts/task_transaction.py <project> --recover
```

临时计划及恢复材料按共享 drafts ignore 规则处理；只读评估使用系统临时目录且不写项目。提交前完成所有语义和链接校验。脚本校验全部输入、独占创建恢复日志、重新核对输入再写入、核对输出；普通失败回滚。进程中断时日志保留于 `.ai/ledev/drafts/task-transaction.json`；下一次任务生命周期写操作及索引写操作前先检查并恢复。恢复遇到用户后续修改时停止并报告冲突，不覆盖用户修改。不依赖 Git。

提交后核对索引 --check、正文唯一性、附件字节校验、状态不变和受影响链接；发现问题用新的完整修复计划处理，不回放旧备份覆盖新修改。并发编辑无法靠文件锁完全阻止，执行期间应避免其他写入者；若输入变化，重新评估后再生成计划。

## state 收敛

state 只保留当前任务及关联任务链接、阶段、关键进度、阻塞/等待、下一步、必要验证命令和最多 10 条近期关键事件。先逐条核对：重复历史可移出；独有决策、验证及交接证据先转存对应任务；归属不明则保留并报告。转存时修复相对路径，保留事件时间和来源。不要截断行数或整块删除历史。

归档不自动触发 context；若 state 指向归档任务，必须修复链接。
